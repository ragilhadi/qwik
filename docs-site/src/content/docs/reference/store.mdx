## Location

- **Linux/macOS:** `$XDG_CONFIG_HOME/qwik/aliases.toml` (usually
  `~/.config/qwik/aliases.toml`)
- **Windows:** `%APPDATA%\qwik\aliases.toml`
- Override both with the `QWIK_CONFIG_DIR` environment variable — see
  [Environment Variables](/reference/environment/)

## Format

The store is human-readable TOML, safe to edit by hand:

```toml
version = 1

[aliases.gs]
command = "git status"
tag = ["git"]
group = "git"
description = "Quick git status"
enabled = true
created_at = "2026-05-10T10:00:00Z"
updated_at = "2026-05-10T10:00:00Z"
last_used = "2026-05-10T11:30:00Z"
run_count = 42
```

## Safety guarantees

- **Backups:** every destructive operation writes to
  `qwik/backups/aliases-<timestamp>.toml` (last 20 kept)
- **Atomic writes:** temp file + rename to prevent corruption
- **Concurrent access:** a file lock guards the store so two simultaneous
  qwik invocations can't interleave writes

## Store versioning

qwik writes a `version = N` field to the top of `aliases.toml` describing
the schema of the file. On load:

- If the file's version is **older** than the current schema, qwik
  auto-migrates it forward (one migrator per version step) and backs up the
  pre-migration file before writing the new shape.
- Migration is **forward-only** — downgrade is not supported; restore from
  a backup (see `qwik doctor`) instead.
- If the file's version is **newer** than the version qwik understands,
  qwik refuses to load it and points at `qwik doctor` — typically you need
  to upgrade qwik to a newer release.

## When to hand-edit

Hand-editing is supported for quick tweaks, but prefer `qwik edit <name>` —
it validates on save and goes through the same locking as the CLI. If you
do edit by hand, keep the `version` field intact.
