## Why qwik?

<CardGrid stagger>
	<Card title="Two ways to run" icon="seti:shell">
		Type <code>gs</code> as a native shell command after a one-time hook install, or run <code>qwik -r gs</code> anywhere — scripts, CI, restricted shells — with no setup at all.
	</Card>
	<Card title="Arguments done right" icon="seti:config">
		Template aliases with <code>{"{1}"}</code>, <code>{"{name}"}</code>, <code>{"{&#64;}"}</code>, <code>{"{*}"}</code>, and <code>{"{1:-default}"}</code>. Missing required arguments produce clear errors, never silently-empty output.
	</Card>
	<Card title="Cross-platform" icon="window">
		Rendered natively for bash, zsh, fish, PowerShell, cmd, Nushell, and Xonsh — with shell-aware quoting chosen by the shell that will run the command.
	</Card>
	<Card title="Safe by default" icon="padlock">
		Conflict detection against builtins and <code>$PATH</code>, atomic writes with rolling backups, quoted runtime substitution, and trust-boundary previews before any import.
	</Card>
	<Card title="Organized" icon="star">
		Tags, groups, fuzzy search, usage stats, and an interactive picker — your alias store stays discoverable as it grows.
	</Card>
	<Card title="Shareable" icon="link">
		Export and import TOML files, sync through a dedicated git repo, or point an overlay at a team alias repository — read-only and shadow-safe.
	</Card>
	<Card title="Fast startup" icon="rocket">
		Interactive dependencies load lazily and shell renderers are cached, so hook-time invocations like <code>qwik init</code> stay quick.
	</Card>
	<Card title="Extensible" icon="puzzle">
		Add your own shell renderers and CLI commands through Python entry points — qwik discovers them automatically.
	</Card>
</CardGrid>

## Use it in 30 seconds

```bash
# install (pipx or uv)
pipx install qwik

# register an alias and install the shell hook
qwik add gs "git status"
qwik init bash --install
source ~/.bashrc

gs                      # native shell alias
qwik -r gs              # same thing, no hook needed
```
